# 管理员 CRUD 入门指南

这份指南面向第一次维护网站的人。日常新增板块和发布帖子都可以在浏览器后台完成，不需要修改源码。

## 1. CRUD 是什么

CRUD 是四种最常用的数据操作：

| 字母 | 英文 | 在这个网站里的操作 |
|---|---|---|
| C | Create | 新建板块或帖子 |
| R | Read | 查看板块和帖子列表 |
| U | Update | 改名称、正文、颜色、排序或状态 |
| D | Delete | 删除空板块或删除帖子 |

## 2. 打开管理后台

本地开发时先启动网站：

```powershell
cd D:\Code\my-blog\ai-forum
npm.cmd run dev
```

打开：

```text
http://localhost:3000/studio/sign-in
```

本地没有配置管理员密码时，开发密码是：

```text
ai-forum-local-admin
```

正式服务器必须在 `.env` 中设置 `ADMIN_PASSWORD_HASH`，不能继续依赖开发密码。

登录后的顶部有两个入口：

- **帖子管理**：创建、查看、编辑和删除内容。
- **板块管理**：维护左侧的 ChatGPT、工具箱以及以后新增的板块。

普通访客看不到后台操作按钮，也不能调用管理接口。

## 3. 板块 CRUD

### 新建板块

进入“板块管理”，点击“＋ 新建板块”，依次填写：

- **板块名称**：访客看到的名称，例如 `AI 绘画`。
- **网址标识**：网址中的短名称，例如 `ai-image`。只能使用小写字母、数字和短横线。
- **板块说明**：说明这里收录什么内容。
- **板块颜色**：左侧导航和帖子列表中的识别色。
- **显示顺序**：数字越小越靠前。

点击“创建板块”后，它会自动出现在左侧分类导航和帖子编辑器的分类下拉框里。

### 查看板块

板块列表会显示：

- 名称和说明
- 网址标识
- 颜色和排序
- 帖子总数
- 已发布数量和草稿数量

### 修改板块

点击板块右侧“编辑”。名称、说明、颜色和顺序都可以修改。

网址标识是只读的。例如板块从“工具箱”改名为“实用工具”后，地址仍然是 `/c/toolbox`，以前分享出去的链接不会失效。

### 删除板块

空板块可以删除。只要里面还有已发布帖子或草稿，后台就会拒绝删除并显示：

```text
板块中还有帖子，请先移动或删除这些帖子
```

处理方法：进入“帖子管理”，编辑这些帖子，把分类改到其他板块；确认原板块变成 0 篇帖子后再删除。系统还会强制保留至少一个板块。

## 4. 帖子 CRUD

### 新建帖子

进入“帖子管理”，点击“＋ 新建帖子”。填写标题、分类、标签和 Markdown 正文。

所有板块都可以填写可选的“外部网站地址”。适合聚合工具、教程原文或资源网站；不需要外链时留空即可。

编辑器底部：

- **保存草稿**：只有管理员能在工作台看到。
- **发布帖子**：访客可以在首页和板块页看到。

### 查看和查找帖子

帖子管理列表支持“全部、已发布、草稿”筛选，也可以按标题搜索。列表会显示所属板块、状态、浏览量和更新时间。

### 修改帖子

点击帖子右侧“编辑”，可以修改标题、分类、标签、正文、外部网站地址、摘要和置顶状态。已经发布的帖子点击“保存修改”后立即更新公开内容。

把已发布帖子保存为草稿后，它会从公共网站隐藏，但仍保留在后台。

### 删除帖子

点击帖子右侧“删除”并确认。目前没有回收站，删除后不能在后台撤销。重要内容应先备份数据库。

## 5. 标签怎么维护

标签不需要单独创建。编辑帖子时用中文或英文逗号分隔，例如：

```text
提示词, 工作流, 图片工具
```

已发布帖子使用的标签会自动进入左侧折叠标签列表。如果要删除某个标签，需要编辑所有使用它的帖子并移除该标签；没有公开帖子使用后，它会自动消失。

## 6. 这个 DB 是什么

当前数据库是 **SQLite**，由 `better-sqlite3` 驱动。它把板块、帖子、标签、浏览记录和管理员会话保存在一个文件中：

```text
本地开发：.data/ai-forum.db
Docker：  data/ai-forum.db
```

不要用记事本或 VS Code 直接编辑这个二进制文件。

### SQLite 和 MySQL 的区别

| 对比 | SQLite | MySQL |
|---|---|---|
| 运行方式 | 嵌入应用，主要是一个文件 | 独立数据库服务 |
| 安装维护 | 很少，项目启动就能使用 | 需要安装、账号、端口和服务维护 |
| 备份 | 停止写入后复制数据库文件 | 使用数据库备份工具或快照 |
| 并发读取 | 很好 | 很好 |
| 大量并发写入 | 单写入者模型，不适合很多人同时发帖 | 更适合高并发写入 |
| 多台应用服务器 | 不适合共享同一个本地文件 | 适合多台应用连接同一数据库 |
| 当前项目 | 推荐 | 暂时没有必要 |

你的网站目前只有管理员写入，大多数访问是读帖子，SQLite 更轻、更省事。以后开放大量用户注册发帖、评论，或者同时运行多台网站服务器时，再评估 MySQL 或 PostgreSQL。

迁移数据库不是把 `.db` 改名：需要替换驱动、迁移表结构和数据，并重新测试所有查询。

## 7. 备份数据库

本地备份前先在运行 `npm.cmd run dev` 的窗口按 `Ctrl+C` 停止网站，然后复制：

```powershell
New-Item -ItemType Directory -Force backups
Copy-Item .data\ai-forum.db backups\ai-forum-2026-08-24.db
```

Docker 服务器备份步骤在项目 `README.md` 的“数据备份与恢复”章节。备份文件包含草稿和管理员会话，不要提交到 Git 或放进公开下载目录。

## 8. 源码地图

| 文件或目录 | 负责什么 |
|---|---|
| `app/pages/studio/index.vue` | 帖子管理列表 |
| `app/components/TopicEditor.vue` | 帖子新建和编辑器 |
| `app/pages/studio/categories/` | 板块管理页面 |
| `app/components/CategoryEditor.vue` | 板块表单 |
| `app/layouts/studio.vue` | 后台顶部导航 |
| `server/api/studio/topics/` | 帖子管理接口 |
| `server/api/studio/categories/` | 板块管理接口 |
| `server/utils/validation.ts` | 管理员输入校验 |
| `server/utils/database.ts` | SQLite 表和增删改查逻辑 |
| `app/assets/css/main.css` | 公共页面与后台样式 |

正常增加板块和帖子不要改这些文件，直接使用后台。只有要改变功能、字段或页面布局时才修改源码。

## 9. 安全修改源码

开始前确认工作区，并创建新分支：

```powershell
git status
git switch -c feature/修改名称
```

开发时：

```powershell
npm.cmd run dev
```

修改完成后：

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
npm.cmd run test:e2e
```

最后查看修改并提交：

```powershell
git status
git diff
git add 你实际修改的文件
git commit -m "feat: 简短说明"
```

不要手动修改 `node_modules`、`.nuxt`、`.output` 和 `package-lock.json`。前三者是生成文件；`package-lock.json` 应交给 npm 在安装依赖时维护。
