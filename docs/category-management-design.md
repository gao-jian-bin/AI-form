# 后台板块与帖子 CRUD 设计

日期：2026-08-24

## 目标

在现有轻量论坛中补齐管理员板块 CRUD，并将已有帖子 CRUD 改造成完全由数据库板块驱动的编辑流程。部署后，管理员可以通过工作台维护内容，普通访客只能读取公开帖子和公开板块。

## 范围

本次包含：

- 管理员创建、查看、修改、排序和删除板块。
- 管理员创建、查看、修改和删除帖子。
- 帖子编辑器动态读取板块，不再写死 ChatGPT 和工具箱。
- 所有板块都可以为帖子填写可选的外部网站地址。
- 更新面向初学者的后台操作和源码维护文档。

本次不包含：

- 访客登录、注册、发帖或回复。
- 板块回收站、帖子回收站和批量迁移。
- 修改板块 Slug 后的旧网址重定向。
- MySQL 适配和多台应用服务器部署。

## 数据与业务规则

继续使用现有 SQLite `categories`、`topics` 和 `admin_sessions` 表，不新增数据库依赖。

板块包含名称、Slug、说明、颜色、排序和帖子数量。名称、说明、颜色与排序可以修改；Slug 在创建后保持不变，确保 `/c/<slug>` 旧链接继续有效。创建时 Slug 必须由英文字母、数字和短横线组成并保持唯一。

ChatGPT 和工具箱只在数据库中没有任何板块时作为初始板块创建。应用重启不会再覆盖管理员修改过的名称、说明、颜色和排序。

删除板块前统计该板块内所有已发布帖子和草稿。只要存在任何帖子就拒绝删除，并提示管理员先编辑帖子、将它们移动到其他板块。空板块可以删除。至少保留一个板块，避免帖子编辑器没有可选板块。

帖子仍支持草稿和发布两种状态。所有板块中的帖子都可以填写可选的 HTTP 或 HTTPS 外部网站地址；不再把这个字段限制在 `toolbox` Slug。

## 服务端设计

数据库层增加以下板块操作：

- 列出管理员可见的全部板块和全部帖子数量。
- 按 ID 读取板块。
- 创建板块并检查名称、Slug 和颜色。
- 修改板块的名称、说明、颜色和排序，不修改 Slug。
- 删除空板块，并拒绝删除有帖子的板块或最后一个板块。

增加受管理员会话保护的接口：

- `GET /api/studio/categories`
- `POST /api/studio/categories`
- `GET /api/studio/categories/:id`
- `PUT /api/studio/categories/:id`
- `DELETE /api/studio/categories/:id`

公开的 `GET /api/categories` 保持不变，继续返回公开帖子数量供左侧导航显示。

帖子写入校验不再使用 `chatgpt`、`toolbox` 白名单。请求中的 `categorySlug` 先做格式校验，再由数据库确认板块是否存在。外部网站地址仍执行 HTTP/HTTPS 安全校验。

所有失败响应使用明确的中文信息，包括 Slug 重复、板块不存在、板块仍有帖子和不能删除最后一个板块。

## 管理后台设计

工作台顶部增加两个管理员导航入口：

- 帖子管理
- 板块管理

`/studio/categories` 使用与当前帖子管理一致的表格风格，显示颜色、名称、Slug、排序和全部帖子数。页面提供“新建板块”“编辑”“删除”操作。

新建和编辑使用单独表单页面：

- 新建时填写名称、Slug、说明、颜色和排序。
- 编辑时显示只读 Slug，并允许修改其他字段。
- 表单旁显示简短说明，让初学者理解名称、Slug、颜色和排序的作用。
- 接口失败时在表单或列表中直接显示中文错误，不静默失败。

现有帖子管理继续保留全部、已发布、草稿筛选以及编辑、删除操作。帖子编辑器在打开时请求板块列表，用数据库结果渲染分类下拉框。外部网站地址始终作为可选字段显示。如果没有可用板块，编辑器提示先去板块管理创建板块。

普通访客页面不显示管理按钮；管理员仍通过 `/studio/sign-in` 登录工作台。

## 测试设计

数据库测试覆盖：

- 初始板块只在空数据库创建，并且不会覆盖已修改板块。
- 创建、读取、修改和排序板块。
- 拒绝重复 Slug。
- 拒绝删除有已发布帖子或草稿的板块。
- 拒绝删除最后一个板块。
- 允许删除空板块。

校验测试覆盖板块输入、动态帖子板块和所有板块可填写外部地址。

浏览器测试覆盖管理员登录、新建板块、使用新板块发布帖子、修改板块名称，以及删除空板块。最终运行单元测试、类型检查、生产构建和 Playwright 测试。
