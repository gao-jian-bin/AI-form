# AI 知识论坛初版设计规格

**日期：** 2026-08-20  
**状态：** 已确认  
**项目目录：** `D:\Code\my-blog\ai-forum`

## 1. 目标

创建一个完全独立的个人知识站，以 Discourse 和 Linux.do 的论坛式信息架构为参考，用紧凑的主题列表收录 AI、ChatGPT 和实用工具相关内容。

初版是“站长发布、公众阅读”的内容站：访客无需登录即可浏览和搜索，但不能注册、登录、发帖、回复或修改内容；站长通过不出现在公共导航中的私有管理入口维护帖子。项目不得读取、复用或修改 `D:\Code\my-blog` 中现有 `frontend`、`backend` 或其他应用的代码与数据。

## 2. 成功标准

- 项目位于独立的 `ai-forum` 目录，可单独安装、测试、构建和部署。
- 首页在桌面端呈现论坛式三栏信息结构，在移动端变为清晰的单栏主题流。
- 首期只有 `ChatGPT` 和 `工具箱` 两个一级板块。
- 访客能浏览最新主题、按板块筛选、搜索并阅读主题详情。
- 站长能登录私有后台，创建、保存草稿、编辑、发布、置顶和删除主题。
- 公共页面不显示登录、注册、回复或发帖入口；未授权请求不能修改内容。
- 提供 Docker 化部署、环境变量、数据库持久化和备份说明。
- 桌面端与移动端均通过实际浏览器验收，并满足基本键盘访问和减少动态效果设置。

## 3. 非目标

初版不实现以下内容：

- 公开注册、第三方登录或普通用户账户
- 评论、回复、点赞、收藏、私信、通知和关注
- 徽章、积分、等级、排行榜等社区激励系统
- 多管理员、角色权限或审核工作流
- 邮件订阅、推送通知或站内聊天
- 对 Discourse 核心源码的复制、分叉或修改
- 在线工具本身，例如在站内完成图片压缩或 Base64 解码；工具箱初版只收录和介绍外部工具网站

## 4. 技术方案

采用一个轻量的 TypeScript 全栈应用：

- **应用框架：** Nuxt，负责服务端渲染、页面路由和服务端 API。
- **语言：** TypeScript。
- **数据库：** SQLite；数据库文件通过服务器持久化目录保存。
- **数据访问：** 使用带迁移能力的轻量 ORM，所有表结构变更通过版本化迁移完成。
- **内容格式：** Markdown；保存原文，在展示时通过受控渲染器转换为 HTML，并清理不安全标记。
- **认证：** 单一站长账户；密码只以强哈希保存，登录成功后使用带 `HttpOnly`、`SameSite` 和生产环境 `Secure` 属性的会话 Cookie。
- **部署：** 多阶段 Docker 镜像和 Docker Compose；生产环境由反向代理终止 HTTPS。
- **样式：** 自定义设计令牌和组件样式，不引入对 Discourse 或 Linux.do 品牌素材的复制。

SQLite 适合初期“单站长写、多人读”的负载。数据访问层不得把 SQLite 特有 SQL 泄漏给页面组件，以便将来确有并发写入需求时迁移至 PostgreSQL。

## 5. 信息架构

### 5.1 一级板块

`ChatGPT` 与 `工具箱` 作为一级板块，而不是普通标签，因为它们承担公共导航、内容分区和板块介绍的职责。

- **ChatGPT：** ChatGPT 使用技巧、Prompt、工作流、新功能体验和有趣玩法。
- **工具箱：** 图片压缩、文件转换、Base64 编解码、视频解析以及其他实用网站。

主题可以另外拥有零个或多个细粒度标签，例如 `Prompt`、`图片处理`、`开发工具`。标签不出现在首期一级导航中，但可从主题条目和详情页点击筛选。

### 5.2 公共路由

- `/`：最新主题列表，包含置顶主题。
- `/c/chatgpt`：ChatGPT 板块。
- `/c/toolbox`：工具箱板块。
- `/tag/:slug`：标签筛选结果。
- `/search?q=`：搜索结果。
- `/t/:slug/:id`：主题详情。
- 未匹配路由：带返回首页与搜索入口的 404 页面。

### 5.3 私有管理路由

- `/studio/sign-in`：站长登录。
- `/studio`：主题管理列表。
- `/studio/topics/new`：新建主题。
- `/studio/topics/:id/edit`：编辑主题。

`studio` 不是安全边界；真正的权限控制必须在服务端 API 上完成。公共导航和站点地图不暴露这些入口，但即使访问者知道地址，也不能绕过认证。

## 6. 页面与组件

### 6.1 全局头部

头部包含站点标识、`最新`、`ChatGPT`、`工具箱` 和搜索入口。桌面端保持紧凑单行；移动端保留站点标识和搜索按钮，板块导航成为可横向滚动的次级栏。

公共头部不显示登录或注册入口。

### 6.2 首页

桌面端采用三栏结构：

```text
┌──────────────────────────────────────────────────────┐
│ 站点标识      最新  ChatGPT  工具箱        搜索       │
├──────────┬────────────────────────────┬──────────────┤
│ 板块导航 │ 置顶主题 / 最新主题列表     │ 关于本站     │
│          │                            │              │
│ ChatGPT  │ 标题、摘要、板块、标签      │ 热门主题     │
│ 工具箱   │ 浏览量、更新时间            │ 最近更新     │
└──────────┴────────────────────────────┴──────────────┘
```

- 左栏提供板块说明和主题数量。
- 中栏是页面主体，采用分隔线主题行而不是大型博客卡片。
- 右栏显示简短站点介绍、热门主题和最近更新。
- 小屏幕隐藏左右栏，把板块切换、站点说明和主题流按重要性合并为单栏。

### 6.3 主题列表行

每行显示标题、最多两行摘要、板块、标签、浏览量和更新时间。置顶主题拥有清晰的置顶标识。工具箱主题可以显示外部链接域名，但点击标题仍先进入站内详情，避免访客被意外带离站点。

### 6.4 主题详情

主题详情包含：

- 标题、板块、标签、发布时间、最近更新时间和浏览量
- Markdown 正文，包括代码块、引用、列表、图片和链接
- 工具箱主题的醒目“访问工具”按钮，外部链接在新标签页打开并带安全的 `rel` 属性
- 上一篇、下一篇或同板块相关文章

详情页不模拟虚假的回复数、用户头像或在线状态。站长内容统一显示一个可配置的作者名称。

### 6.5 管理工作台

管理列表按草稿、已发布、置顶和板块筛选，支持标题搜索。编辑器字段包括：

- 标题
- Slug（默认由标题生成，可修改，发布后保持稳定）
- 板块
- 标签
- 摘要（可留空，系统从正文生成）
- Markdown 正文和实时预览
- 工具外链（仅工具箱主题可用）
- 草稿/发布状态
- 置顶状态

删除操作必须二次确认。退出登录后会话立即失效。

## 7. 视觉方向

界面借鉴 Discourse 的内容密度和信息层级，而不复制 Linux.do 的标志、名称、插图或品牌配色。

- **颜色：** 中性灰白背景、深墨色正文、清晰蓝色交互色；ChatGPT 与工具箱使用不同但克制的板块色。
- **字体：** 以高可读性的中文无衬线字体栈为正文，标题使用略紧凑的字重和字距。
- **布局：** 最大内容宽度约 1180–1240px；主题列表以对齐、留白和细分隔线建立节奏。
- **圆角：** 控制在小到中等范围，只用于输入框、按钮和少量容器。
- **动态效果：** 只使用导航状态、主题行悬停和轻微页面进入过渡；遵守 `prefers-reduced-motion`。
- **深色模式：** 根据系统偏好初始化，并允许访客本地切换。

标志性元素是“知识轨道”：主题列表左侧使用连续的细轨道连接板块色标记，既表现持续收录的知识流，也帮助快速扫描板块。其余装饰保持克制。

## 8. 数据模型

### 8.1 `categories`

- `id`
- `name`
- `slug`，唯一
- `description`
- `color`
- `position`
- `createdAt`
- `updatedAt`

初始迁移固定创建 `chatgpt` 和 `toolbox` 两条记录。删除系统板块不属于初版功能。

### 8.2 `topics`

- `id`
- `title`
- `slug`
- `excerpt`
- `contentMarkdown`
- `categoryId`
- `status`：`draft` 或 `published`
- `isPinned`
- `externalUrl`，可空
- `viewCount`
- `publishedAt`，可空
- `createdAt`
- `updatedAt`

公开查询只能返回 `published` 主题。公开详情通过 `id` 定位，slug 用于可读 URL；修改标题不会令旧链接失效。

### 8.3 `tags` 与 `topicTags`

标签名称和 slug 唯一。主题与标签为多对多关系。

### 8.4 `adminSessions`

保存会话令牌的不可逆摘要、创建时间和过期时间，不保存明文令牌。过期会话在登录或管理请求时清理。

站长凭据来自环境变量或首次初始化命令，不在数据库迁移、种子数据或源码中放置默认生产密码。

## 9. 数据流与权限

### 9.1 公共读取

浏览器请求页面，Nuxt 服务端读取已发布主题并输出首屏 HTML；客户端接管后进行筛选和翻页。搜索、板块和标签条件由服务端验证，空查询返回引导信息而不是错误。

浏览量采用单独的受限接口递增，同一访客对同一主题在短时间内只计一次，避免刷新造成明显失真。浏览量是热度参考，不承诺精确分析统计。

### 9.2 管理写入

登录接口验证密码、限制连续失败请求并创建会话。所有创建、更新、发布、置顶和删除接口先在服务端验证会话，再验证请求结构和内容长度。客户端隐藏按钮不能替代服务端鉴权。

发布主题时生成 `publishedAt`；编辑已发布主题不会重置首次发布时间。外部链接只允许 `http` 或 `https` 协议。

### 9.3 Markdown 安全

Markdown 渲染禁用原始 HTML或在输出后进行白名单清理。外部链接加 `noopener noreferrer`。图片 URL 和链接协议必须经过验证，避免脚本协议和危险嵌入。

## 10. 错误处理与状态

- 列表加载失败：保留页面骨架，显示“暂时无法加载主题”和重试按钮。
- 搜索无结果：显示当前关键词并建议切换板块或缩短关键词。
- 主题不存在或未发布：向访客返回 404，不泄露草稿存在性。
- 会话过期：管理 API 返回 401，前端清除本地状态并跳转登录页。
- 表单校验失败：错误显示在对应字段附近，保留未提交内容。
- 发布冲突：基于更新时间拒绝覆盖较新的内容，提示站长刷新后重新确认。
- 数据库或服务器异常：返回不包含堆栈、路径或 SQL 的通用消息，详细信息只写入服务端日志。

## 11. SEO 与可分享性

- 每个公共页面提供准确的标题、描述、canonical URL 和 Open Graph 元数据。
- 自动生成只包含已发布主题的 `sitemap.xml`。
- 草稿、管理路由和登录页设置为不可索引。
- 主题标题使用单个 `h1`，正文保持合理标题层级。
- 页面在禁用客户端 JavaScript 时仍能读取主要正文。

## 12. 测试与验收

### 12.1 自动化测试

- 单元测试：slug 生成、摘要生成、URL 校验、Markdown 清理、查询参数解析。
- 服务端测试：匿名只读、草稿隔离、登录限流、会话过期、主题 CRUD、搜索和浏览量去重。
- 组件测试：主题行、空状态、错误状态、板块切换、编辑器校验。
- 端到端测试：访客浏览流程、站长登录发布流程、编辑/置顶/删除流程、移动端导航。

新增行为遵循先写失败测试、确认失败原因、最小实现、确认通过、再整理代码的循环。

### 12.2 人工视觉验收

- 1440px 桌面宽度下检查三栏对齐、主题密度和长中文标题。
- 390px 手机宽度下检查导航、搜索、主题行和 Markdown 内容。
- 检查浅色与深色模式。
- 仅使用键盘完成公共导航、搜索和管理发布。
- 开启减少动态效果后确认无非必要动画。

## 13. 部署与运维

- 提供 `.env.example`，列出站点 URL、会话密钥、站长密码哈希和数据库路径。
- Docker Compose 只暴露应用端口，SQLite 数据库和上传文件使用命名卷或明确的宿主机目录。
- 反向代理负责域名、HTTPS、压缩和基础请求限制。
- 部署文档包含首次初始化、更新镜像、查看日志、数据库备份和恢复步骤。
- 备份至少包含 SQLite 数据库、上传目录和运行环境配置；备份前执行 SQLite 安全快照或停止写入，不能直接复制正在写入的数据库文件。
- 不在仓库中提交 `.env`、会话密钥、数据库文件、上传文件或生产备份。

## 14. 初始内容

开发种子数据包含约 6–8 篇明确标记为演示内容的主题，用于验证长短标题、代码块、标签、置顶、工具外链和移动端排版。正式交付前可通过初始化命令清除演示内容并创建两个板块，不把演示内容混入生产数据。

## 16. 后续扩展边界

未来若决定开放社区功能，应作为独立阶段重新设计普通用户、邮箱验证、回复关系、审核、举报、通知和反滥用机制。初版不预埋空壳页面或伪功能，但数据访问、路由和组件边界不得阻止后续增加这些能力。
