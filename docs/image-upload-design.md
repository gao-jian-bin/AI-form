# 帖子编辑器图片上传设计

日期：2026-08-29  
状态：已确认采用本地存储轻量方案

## 目标

管理员在帖子编辑器中粘贴、拖入或选择图片后，图片立即上传并自动生成 Markdown。开发阶段文件保存在本机；部署后使用相同机制保存到服务器持久目录，帖子内容不需要改写。

## 为什么现在粘贴没有反应

当前编辑器只接收文本键盘事件，没有图片粘贴或拖放监听，也没有上传 API 和图片存储目录。Markdown 渲染器已经支持 `![说明](地址)`，缺少的是从图片文件生成可访问地址的完整链路。

## 存储方式

- 默认目录：`.data/uploads`。
- 可用环境变量 `UPLOAD_DIR` 改为服务器上的持久目录，例如 `/srv/ai-forum/uploads`。
- 图片 URL 始终使用 `/uploads/年/月/随机文件名.扩展名`，因此从本机迁移到服务器后无需修改 Markdown。
- 部署时将 SQLite 数据库和上传目录一起复制、挂载和备份。
- 本轮不接入 Cloudflare R2、S3 或第三方图床；未来可在保持 URL 接口不变的情况下替换存储实现。

## 编辑器交互

- 支持直接粘贴剪贴板图片。
- 支持拖放图片到正文编辑区。
- Markdown 工具栏增加“上传图片”按钮，支持文件选择和多选。
- 收到图片后在光标处立即插入“正在上传”占位内容；上传完成后替换为 `![原文件名](/uploads/...)`。
- 上传期间显示明确状态并暂时禁用保存，防止帖子保存了尚未完成的占位内容。
- 上传失败时移除占位内容，保留编辑器中的其他文字，并在编辑器顶部显示中文错误提示。

## 服务端接口

- `POST /api/studio/uploads`：仅管理员会话可调用，接收 multipart 图片并返回 `{ url, alt, mimeType, size }`。
- `GET /uploads/**`：公开读取已上传图片，设置正确的 `Content-Type`、长期缓存和 `X-Content-Type-Options: nosniff`。
- 文件名由随机 UUID 生成，不使用用户提供的路径，避免覆盖和目录穿越。
- 原文件名只用于 Markdown 图片说明，并在插入前清理方括号、换行等 Markdown 控制字符。

## 安全限制

- 只接受 JPEG、PNG、WebP 和 GIF。
- 拒绝 SVG、脚本、伪造扩展名和无法识别的文件签名。
- 单张图片最大 10 MiB；一次最多上传 10 张。
- 读取图片时必须验证解析后的绝对路径仍位于上传根目录内。

## 删除策略

本轮不做图片媒体库和自动删除。管理员从 Markdown 中删掉图片引用时，磁盘文件暂时保留，避免误删被其他帖子复用的图片；以后图片量明显增长时再增加“未引用图片清理”功能。

## 本地到服务器迁移

本地开发时，电脑上的 Nuxt 进程就是图片服务器，图片位于项目 `.data/uploads`。正式部署时复制数据库和上传目录，并设置：

```env
DATABASE_PATH=/srv/ai-forum/ai-forum.db
UPLOAD_DIR=/srv/ai-forum/uploads
```

这两个路径必须放在持久磁盘或 Docker volume 中，不能依赖每次部署都会被覆盖的 `.output` 目录。

## 测试与验收

- 单元测试验证图片魔数、扩展名、大小限制和安全路径。
- API 测试验证未登录拒绝、合法图片上传、错误类型拒绝和公开读取。
- 浏览器测试验证粘贴、拖放、文件选择、占位替换、右侧预览和失败提示。
- 最终运行单元测试、端到端测试、类型检查和生产构建。
