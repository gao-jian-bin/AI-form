# 帖子编辑器可用性改进设计

日期：2026-08-29  
状态：已确认

## 目标

在不引入 Discourse 全套运行时的前提下，让现有帖子编辑器获得与 Discourse 相同的核心体验：正确的 Markdown 块级编辑、网页内全屏、清晰可拖动的滚动条，以及可调整的编辑器高度。

## 已确认的问题

- 光标在普通文字末尾点击“引用”会生成 `正文> 引用内容`，缺少块级换行，因此右侧只能渲染成普通段落。
- 编辑框和预览框虽然具备程序滚动能力，但系统覆盖式滚动条几乎不可见，用户无法直观看到和拖动滚动位置。
- 当前没有网页内全屏状态。
- 顶部灰色 grippie 只是装饰，不能像 Discourse 一样拖动调整高度。

## 方案选择

采用“现有浮动编辑器增加状态”的方案：保持帖子列表不跳页，由编辑器自己管理普通、收起和全屏状态。

未采用浏览器 Fullscreen API，因为它会改变浏览器级状态并受权限、手势和退出行为限制；未采用单独编辑页，因为它会破坏当前列表内编辑流程。

## 交互设计

- 标题栏增加全屏按钮；点击后编辑器铺满当前网页视口，再次点击或按 `Esc` 退出。
- 全屏时锁住背景页面滚动，编辑区和右侧预览仍分别滚动；关闭编辑器时无条件恢复页面滚动。
- 编辑区和预览区始终保留稳定的滚动条空间，并显示清晰的轨道与滑块，鼠标可以直接拖动。
- 顶部 grippie 支持鼠标或触控拖动来改变普通模式高度，设置合理的最小和最大高度；全屏或收起时禁用拖动。
- “引用”在当前内容前后自动补齐块级换行。标题、列表和代码块等块级工具同时使用相同的边界规则，避免出现内容粘连。
- 移动端仍保留“编辑 / 预览”单栏切换；全屏使用 `100dvh`，避免地址栏导致高度溢出。

## 实现边界

- 只修改现有 Vue 组件、Markdown 编辑工具和 CSS，不增加第三方前端依赖。
- 不改变帖子 API、数据库结构和现有保存流程。
- 不复制 Discourse 的 Ember 组件，只复用其成熟的交互模式。

## 验收

- 单元测试覆盖行尾插入引用，以及已有 Markdown 引用的安全渲染。
- 浏览器测试覆盖：全屏进入/退出、`Esc` 退出、背景滚动锁定、长文本编辑区与预览区独立滚动、grippie 调整高度，以及移动端全屏可用。
- 最后运行单元测试、端到端测试、类型检查和生产构建。
