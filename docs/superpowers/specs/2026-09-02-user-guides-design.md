## 文章一：Clash Verge 节点异常排查

文章采用由近到远的排障顺序：

1. 先区分单节点、全部节点、单设备和整个网络故障。
2. Windows 用户临时退出第三方安全软件，并通过 Windows 安全中心临时关闭实时保护和当前网络配置文件的防火墙。
3. 明确说明关闭保护只用于诊断；测试完成后立即恢复。若关闭后恢复正常，应添加可信程序或文件夹排除项，而不是长期关闭安全功能。
4. 解释 Clash Verge 以管理员权限运行时，资源管理器拖入 YAML 可能受 Windows UIPI 完整性级别隔离影响。解决方式是彻底退出后以普通权限启动，或右键 YAML 选择“打开方式”。
5. 若仍然失败，通过换设备、换 Wi-Fi/手机流量、检查服务端端口和客户端日志，判断是运营商线路、DNS/UDP、服务端故障、IP/域名受干扰，还是订阅与协议参数问题。
6. 单列 2026 年 7 月以后 Xray-core 26.7.11+ 与 Mihomo 的 VLESS + REALITY 兼容问题。说明 Mihomo 在 REALITY 握手中报告的客户端版本为 `1.8.2`；服务端可把 `minClientVer` 设置为 `1.8.2`，若需要更宽兼容范围可按社区方案使用 `1.0.0`。该设置只适用于自己管理的服务端，不能泛化为所有“节点超时”。

文章引用 Microsoft 官方安全说明，以及 Xray、Mihomo、3x-ui 项目的原始代码或 Issue。

## 文章二：Codex Desktop Windows 入门

文章覆盖：

1. 从 OpenAI 官方 Windows 文档进入下载；网页可能转到 Microsoft Store。
2. Microsoft Store 经当前代理节点无法加载时，先退出代理再直连搜索 `Codex`，也提供官方 `winget install --id 9PLM9XGG6VKS -s msstore` 作为替代安装方式。
3. 安装后使用 ChatGPT 账号登录并选择项目目录。
4. 从左下角账户菜单打开 Usage，或在对话框输入 `/status` 查看上下文占用和速率限制。
5. 在 Settings > Usage & billing 中检查是否存在可用的 Full reset，解释其适用范围以界面为准，并提醒留意过期时间。
6. 说明当前 Windows 客户端使用 Electron/Chromium 桌面架构。多进程运行会带来较高的基础内存开销；长对话、多个窗口、终端与插件也可能加剧卡顿，但不能仅凭内存占用断言发生泄漏。
7. 卡顿教程使用明确的待替换标记 `{{CODEX_DESKTOP_LAG_URL}}`；CLI 教程链接到现有站内地址 `/t/codex-cli-beginner-guide/10`。

文中使用用户提供的五张截图，并引用 OpenAI 官方 Windows、Slash commands、Pricing 与 Changelog 页面。

## 文章三：开启 Codex 1M 上下文

文章给出个人配置文件路径 `~/.codex/config.toml`。Windows 用户同时看到实际路径示例 `%USERPROFILE%\.codex\config.toml` 和 PowerShell 打开命令。

配置内容为：

```toml
model = "gpt-5.6-sol"
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

文章区分三组数字：

- GPT-5.6 Sol 的官方模型规格是 1,050,000 tokens。
- 当前 Codex 0.152.1 本地模型目录默认给 GPT-5.6 Sol 配置 272,000，按 95% 有效比例约显示 258,400。
- 当前目录同时给出 872,000 的客户端最大窗口，按 95% 计算约为 828,400，因此启用大窗口后 `/status` 可能显示约 828K，而不是整整 1M。不同客户端版本、模型目录和已有系统上下文可能产生约 855K、858K 等不同显示值。

不把配置描述成凭空增加模型能力：它请求 Codex 使用更大的上下文预算，而最终有效值仍受模型、客户端目录、服务端策略、自动压缩阈值和当前已占用上下文共同限制。

结尾提醒非 Pro 用户谨慎开启。长上下文会让每轮携带更多历史、文件和工具结果，官方也说明上下文大小会影响用量；GPT-5.6 Sol 超过 272K 输入后会进入长上下文计费倍率，因此额度可能明显加速消耗。

## 写作与验收标准

- 使用自然、直接的中文，保留少量口语感，不使用营销话术。
- 步骤能够由 Windows 新手独立照做。
- 危险或降低防护的操作必须带恢复提示和更安全的长期方案。
- 版本相关结论注明日期或版本，避免教程更新后继续被当作永久规则。
- 三篇文章中的命令、路径、内部链接、图片路径和 Markdown 围栏均做机械检查。
- 正文不直接修改论坛数据库，也不自动发布。

## 最快发布方式

当前论坛没有 Markdown 批量导入功能。最省事的现有流程是进入管理后台，新建帖子，按文件头注释填写标题、板块、标签和摘要，再复制正文；图片通过 Composer 的图片按钮上传，并用返回的 `/uploads/...` 地址替换草稿中的相对路径。

如果以后需要经常批量发文，可以另做一个只创建草稿、不直接发布的导入脚本；这不属于本次三篇文章的范围。
