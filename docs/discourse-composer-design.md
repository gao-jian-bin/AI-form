# Discourse 式管理员 Composer 设计

## 目标

把当前独立的帖子编辑页面替换为轻量的 Discourse 式底部 Composer。管理员从公开帖子页或后台帖子列表点击铅笔后，在当前页面底部直接编辑；普通访客始终看不到编辑入口，也不能调用管理接口。

本设计移植 Discourse Composer 的布局与核心交互，但继续使用本项目的 Nuxt、Vue、Nitro 和 SQLite，不引入 Ember、Rails 或 Discourse 的完整依赖。

## 用户体验

### 打开与关闭

- 管理员登录后，公开帖子页显示小铅笔“编辑帖子”。
- 后台帖子列表中的编辑操作改为打开 Composer，不再离开列表。
- Composer 固定在窗口底部，当前帖子或列表保留在背景中。
- 点击收起后只保留标题栏，再次点击恢复。
- 点击关闭时，如果内容发生变化，先确认是否放弃修改；没有变化时直接关闭。
- 保存成功后关闭 Composer，并刷新背景页面的数据。

旧地址 `/studio/topics/:id/edit` 继续保留兼容性。直接访问时加载对应帖子并打开 Composer，避免已有书签失效。新建帖子 `/studio/topics/new` 复用同一 Composer。

### 编辑区域

Composer 采用 Discourse 当前重设计版的主要结构：

1. 顶部拖拽条视觉区和操作标题栏。
2. 标题输入框独占一行。
3. 板块选择器、标签选择器和外部地址位于字段行。
4. 桌面端 Markdown 编辑和安全预览左右分栏。
5. 工具栏位于编辑区底部、发布操作之前，与 Discourse Composer 一致。
6. 手机端使用“编辑 / 预览”切换，操作按钮保持可见。
7. 底部保留保存草稿、发布或保存修改以及保存状态。

本轮不实现图片上传、用户提及、私信、编辑历史、富文本模式和跨设备自动草稿。

## 组件边界

### `useAdminComposer`

全局组合式状态，负责：

- 当前模式：新建或编辑。
- 当前帖子 ID 和加载后的帖子数据。
- 打开、收起、展开和关闭。
- 保存成功后的刷新通知。
- 防止多个 Composer 同时打开。

### `AdminComposerHost`

挂载在 `app.vue`，保证公开布局和后台布局使用同一个 Composer。它负责加载受保护的帖子数据、渲染 Composer、处理加载和错误状态，不负责数据库读写细节。

### `TopicEditor`

继续作为实际表单，但改造成可嵌入 Composer Host 的组件。它负责表单状态、Markdown 工具、预览、脏状态和保存。保存成功通过事件通知 Host，不自行跳转页面。

### `TagChooser`

独立的轻量多选组件，负责：

- 显示已选标签块并支持移除。
- 打开后罗列全部已知标签及使用次数。
- 按名称搜索，键盘上下选择并回车添加。
- 搜索无结果时创建新标签。
- 去重且最多选择 8 个标签。

## 标签数据流

新增受管理员权限保护的 `GET /api/studio/tags`。它返回所有至少被一篇帖子或草稿使用的标签，并按使用次数、名称排序。公开的 `/api/tags` 继续只返回已发布帖子使用的标签，避免草稿信息泄露。

打开 Composer 时并行读取板块和管理员标签。`TagChooser` 使用字符串数组作为值，保存时直接把数组发送到现有帖子接口。后端现有校验继续负责去重、清理空值和限制最多 8 个标签；输入新名称后，现有 `saveTopic` 流程负责创建并关联标签。

从所有帖子移除的孤立标签不出现在选择器中，避免列表不断积累废弃名称。

## 权限与错误处理

- 公开页面只在 `/api/auth/session` 返回已认证时显示铅笔。
- 所有帖子读取、标签读取和保存仍由服务端 `requireAdmin` 校验；前端隐藏按钮不作为安全边界。
- 帖子加载失败时 Composer 显示明确错误并允许关闭。
- 标签接口失败时仍可手动创建标签，但显示“已有标签暂时无法加载”。
- 保存失败时保留当前输入，不关闭 Composer。
- 切换路由或关闭有未保存内容的 Composer 时要求确认。

## 验收与测试

- 数据库测试：管理员标签包含已发布和草稿使用的标签，不包含孤立标签，排序正确。
- HTTP 测试：未登录不能读取 `/api/studio/tags`。
- 组件测试：标签搜索、多选、移除、创建、去重和 8 个上限。
- 浏览器测试：管理员从公开帖子页点击铅笔打开底部 Composer，修改内容后保存并看到背景刷新。
- 浏览器测试：后台列表点击编辑不发生页面跳转。
- 浏览器测试：有未保存内容时关闭会确认。
- 响应式测试：桌面左右分栏，390px 宽度下编辑、预览和保存操作可用且无页面横向溢出。
